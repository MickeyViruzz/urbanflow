UrbanFlow · Data Engineering Mini Project

System architecture

Public, attributed data sources flow through a reproducible Python ETL pipeline into PostgreSQL and are exposed through a typed FastAPI service to the analytical web interface.
01Public sources
Open-MeteoWeather archive + forecast API · CC BY 4.0
OpenStreetMapOverpass construction ways · ODbL
Mumbai Traffic PolicePublic notices · robots-aware BeautifulSoup parser
Demonstration datasetSynthetic records · origin = demo · clearly labelled
No restricted source is bypassed. Failed collection is logged; records are never invented.
→
02Python ETL
01Extract with Requests, BeautifulSoup and public APIs
02Clean HTML, normalise dates and text
03Classify category; extract Mumbai location; summarise
04Validate fields, Mumbai coordinates and source URLs
05Deduplicate with stable SHA-256 fingerprints
06Load records and write a collection log per source
Re-running a source updates changed records and counts duplicates instead of inserting them again.

Tailwind design system · responsive desktop/tablet/mobile layouts · explicit loading, empty and error states.
Request-time services: Nominatim geocoding and OSRM routing. OSRM duration is a free-flow estimate, not live traffic.
Data honesty: OSM records use status “unknown” and a road-segment centre; synthetic records are always labelled and separated.
Traceability: Every incident retains external ID, source URL, publication/collection time, origin, classification method and raw source payload.
